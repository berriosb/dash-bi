# Drizzle ORM & Database Guidelines (dash-bi)

Comprehensive best practices guide for Drizzle ORM (v0.38) and PostgreSQL 16 in the `dash-bi` codebase.

---

## 🛑 Non-Negotiable Project Rules (CRITICAL)

### 1. Multi-Tenant RLS Isolation
EVERY application database query targeting tenant data MUST be wrapped inside `withOrgContext()`.
Never query tenant tables directly via un-isolated `db.select()` or `db.query`.

```ts
// ❌ WRONG — Bypasses multi-tenant RLS isolation!
const dashboards = await db.select().from(dashboardsTable).where(eq(dashboardsTable.orgId, orgId));

// ✅ CORRECT — RLS isolated via withOrgContext
import { withOrgContext } from "@/db";

const dashboards = await withOrgContext(orgId, async (tx) => {
  return await tx.select().from(dashboardsTable);
});
```

### 2. NO Raw SQL (ESLint Rule Enforcement)
Raw SQL strings (`db.execute(sql`...`)`) are strictly blocked by the `dash-bi/no-raw-db-queries` ESLint rule. Always use the Drizzle Query Builder or Relational Query API (`tx.query.*`).

### 3. AI-Generated SQL Validation
All dynamic SQL queries generated by LLMs MUST pass through `validate-query` before execution and execute using the read-only DB role (`dashbi_readonly`).

## 📐 Schema Design Patterns

### 1. Identity Columns & Naming Conventions
- Database column names MUST use `snake_case`.
- TypeScript property names MUST use `camelCase`.
- Primary keys MUST use `uuid()` or PostgreSQL identity columns (`generatedAlwaysAsIdentity()`). Avoid `serial()` for new tables.

```ts
import { pgTable, text, timestamp, uuid, jsonb } from "drizzle-orm/pg-core";

export const dashboardsTable = pgTable("dashboards", {
  id: uuid("id").primaryKey().defaultRandom(),
  orgId: uuid("org_id").notNull(),
  title: text("title").notNull(),
  config: jsonb("config").$type<DashboardConfig>().notNull().default({}),
  createdAt: timestamp("created_at", { withTimezone: true }).defaultNow().notNull(),
  updatedAt: timestamp("updated_at", { withTimezone: true }).defaultNow().notNull(),
});
```

### 2. Inferring TypeScript Types
Always infer types directly from Drizzle table schemas using `InferSelectModel` and `InferInsertModel`:

```ts
import { type InferSelectModel, type InferInsertModel } from "drizzle-orm";
import { dashboardsTable } from "./schema";

export type Dashboard = InferSelectModel<typeof dashboardsTable>;
export type NewDashboard = InferInsertModel<typeof dashboardsTable>;
```

### 3. PostgreSQL Arrays & JSONB Columns
```ts
// Postgres native string array with default empty array
tags: text("tags").array().notNull().default(sql`'{}'::text[]`),

// Strongly-typed JSONB column
metadata: jsonb("metadata").$type<{ viewsCount: number; isPublic: boolean }>().default({ viewsCount: 0, isPublic: false }),
```

## ⚡ Query Patterns & Performance

### 1. Relational Queries (Avoid N+1)
Use Drizzle's relational query API (`tx.query`) to fetch nested data cleanly without writing manual join boilerplate.

```ts
const userWithDashboards = await withOrgContext(orgId, async (tx) => {
  return await tx.query.usersTable.findFirst({
    where: (users, { eq }) => eq(users.id, userId),
    with: {
      dashboards: true,
      roles: {
        with: {
          permissions: true,
        },
      },
    },
  });
});
```

### 2. Partial Selection & Projections
Select only the columns needed to optimize memory and transfer payload:

```ts
const dashboardTitles = await withOrgContext(orgId, async (tx) => {
  return await tx
    .select({
      id: dashboardsTable.id,
      title: dashboardsTable.title,
    })
    .from(dashboardsTable);
});
```

## 🔄 Migrations & DB CLI Workflow

All database commands must be executed from the `./app/` directory:

```bash
# Generate a new SQL migration file after modifying schema files in src/db/
pnpm db:generate

# Execute pending SQL migrations against Postgres
pnpm db:migrate

# Apply multi-tenant RLS policies (MANDATORY after running migrations or creating new tables)
pnpm db:setup-rls

# Launch Drizzle Studio (web UI for inspecting local data)
pnpm db:studio

# Direct schema push (Dev-only, DO NOT use in production or shared branches)
pnpm db:push
```
